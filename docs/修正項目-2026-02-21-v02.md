## 1. Service 層直接依賴 HTTP 物件（高）
狀態：已完成

### 規範
- Service 層不可依賴 `req` / `res`。

### 完成結果（摘要）
- `src/services/user-password-service.ts`、`src/services/user-security-service.ts` 已移除 `Request` 依賴。
- `handleAccessTokenBlackList` 改為接收純資料（authorization header）。
- Controller 改由 `req.headers.authorization` 傳入。

### 修正方向
- 將 Service 入參改為純資料（例如 token、headers、userId）。
- 黑名單處理由 Controller 解析必要資料後傳入 Service，或下放到專用 utility 並以純參數呼叫。

## 4. 錯誤處理責任與 logging 策略不一致（中高）
狀態：已完成

### 規範
- 錯誤 logging 應由 error middleware 統一負責，避免多層重複記錄。

### 已完成範圍
- request flow 已統一由 error middleware 記錄錯誤。
- side-effect logging 已調整為 `warn`，避免與主流程錯誤重複記錄。
- `src/middlewares/check-permission.ts` 發生例外時改為 `next(err)`，交由 error middleware 統一記錄。
- `src/middlewares/validate-avatar-file.ts` 發生例外時改為 `next(err)`，移除重複記錄。
- `src/middlewares/authenticate-tokens.ts` 移除 token 驗證失敗的重複 `error` logging（回傳 401）。
- 舊版 `src/middlewares/rate-limit/limit-create-by-ip.ts` 已移除，統一使用 `rate-limit/` 系列 limiter。
- `src/controllers/admin-controllers.ts` 的 audit side-effect 失敗 `warn` 已補上錯誤物件。

### 修正方向
- 釐清例外場景（bootstrap、cron 可保留獨立 logging）。
- 一般 request flow 由 middleware 統一記錄。
