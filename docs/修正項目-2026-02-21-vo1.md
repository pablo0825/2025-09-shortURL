# 專案修正項目清單（依 AGENTS.md 掃描）

> 歷史版本文件（vo1）。內容為 2026-02-21 初次掃描快照，部分項目已在 `docs/修正項目-2026-02-21-v02.md` 完成修正；請以 v02 為主。

掃描日期：2026-02-21  
狀態：僅掃描與比對，尚未開始修改程式碼

## 一、專案結構不符（高優先）
1. 缺少核心規範檔案與目錄：`src/app.ts`、`database/schema.sql`、`tests/`、`.env.example`。
2. 目錄分層與命名不符：目前使用 `src/route`、`src/controller`、`src/service`、`src/dao`、`src/zod`、`src/type`，規範要求 `src/routes`、`src/controllers`、`src/services`、`src/repositories`、`src/schemas`、`src/types`。
3. `src/routes` 目前為空，實際路由在 `src/route`。

## 二、分層架構違規（高優先）
1. Controller 直接操作 DB/Redis，未遵守 `Route -> Controller -> Service -> Repository -> Database`。
2. Service 層依賴 HTTP 物件（`req`）。
3. Repository 層缺失（現有 `dao` 不足以涵蓋所有查詢）。

## 三、TypeScript / 編碼風格規範落差（高優先）
1. `tsconfig.json` 使用 `CommonJS`，規範要求 ESM。
2. 存在 `default export`。
3. 存在 `any` 型別。
4. 物件型別大量使用 `type` 而非 `interface`。
5. 多個檔名不符 kebab-case。
6. 部分檔案為 UTF-16（`src/controller/user.controllers.ts`、`src/service/user.service.ts`、`src/dao/user.dao.ts`），維護風險高。

## 四、驗證與型別來源規範落差
1. Zod schema 目錄為 `src/zod`，規範要求 `src/schemas`。
2. 型別未普遍由 `z.infer` 推導，仍有大量手寫型別。

## 五、DB / SQL 規範落差（高優先）
1. `Pool` 不在 `src/db/pool.ts`（目前為 `src/pool.ts`）。
2. 大量 SQL 不在 repository 層，散落 controller/utils。
3. 存在 SQL 動態字串組裝（需改為規範方式，避免拼接風險）。

## 六、Redis / 快取規範落差（高優先）
1. 沒有 `src/lib/cache.ts` 統一封裝，現況大量直接 import `redisClient`。
2. Cache-aside 流程分散在 middleware/controller，不由 service 層統一主導。

## 七、錯誤處理與日誌規範落差（高優先）
1. 缺少全域 error middleware。
2. Controller 普遍自行 `try/catch` 並直接回應錯誤，與規範不一致。
3. 存在 `catch {}` 的 silent catch。
4. 未建立統一 logger（`src/lib/logger.ts` 不存在），大量使用 `console.log/error/warn`。

## 八、安全規範落差（高優先）
1. 未初始化 `helmet`。
2. 未見集中式 CORS 設定。
3. 部分 API route 的認證/授權/限流套用不一致（例如部份路由無 `authenticate` 或無 limiter）。
4. `auth` 路由中 `/logout` 未套用 `authenticate` 與 limiter，安全鏈不完整。
5. `src/index.ts` 未掛載 `user` 路由（僅掛載 `/api/link`、`/api/auth`），導致使用者 API 路徑缺失。

## 九、測試與 CI 規範落差（高優先）
1. `package.json` 缺少 `typecheck`、`lint`、`test`、`coverage` scripts。
2. 無 `tests/` 目錄與 Vitest 測試體系。

## 十、其他明顯問題
1. `src/route/user.route.ts` 檔尾確定缺少 export（路由未匯出）。
2. `refresh_token` 的 INSERT SQL 欄位重複出現 `device_info`（`auth.controllers.ts` 多處），屬於功能性錯誤風險。
3. `src/utils/totp.ts` 含啟動副作用 `console.log(generateTotpSecret())`，會在載入模組時輸出敏感資訊風險。
4. `dotenv.config()` 分散於多個模組（`pool`、`jwtProvider`、`sendEmail`），環境變數初始化未集中管理。
5. 存在吞錯寫法 `.catch(() => {})`（`writeLogToDB.ts`），不符合錯誤處理規範。
6. `tsconfig.json` 僅 include `src`，未覆蓋 `tests`，與測試規範不一致。
7. 檔案位置與規範不一致（例如 `src/table.sql`、`src/queries.ts` 在根層流程中角色不明）。
