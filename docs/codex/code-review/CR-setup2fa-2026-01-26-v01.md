## TL;DR（最重要 5 點）
- `src/controller/user.controllers.ts` 的 `setup2fa()` 將 `secret` 以可解密形式暫存於 Redis，若 Redis 被讀取或權限外洩，2FA secret 可能被還原
- `setup2fa()` 未檢查使用者是否已啟用 2FA，可能被重複開啟流程造成 UX 混亂與無效 pending key 累積
- `setup2fa()` 回傳完整 `qrCode` Data URL，若前端紀錄或外洩，等同直接暴露 TOTP secret
- `issuer` 與 `accountName` 固定或單純取 email，缺乏環境化與租戶/品牌識別，容易造成多環境重複帳號混淆
- 缺少可審計的 user_log 記錄（開始設定 2FA），不利資安稽核與可疑行為追蹤

## High risk issues（安全或資料風險，需說明影響與建議方向）
- `setup2fa()` 在 Redis 儲存可解密的 `secret`（以 `encrypt()` 再存入 `encrypted/iv/authTag`），若 Redis 被讀或金鑰洩漏，攻擊者可還原 TOTP secret，等同接管 2FA
  影響：2FA 被繞過，帳號保護失效
  建議：改用一次性加密金鑰或改存 HMAC/不可逆資料並在 `enable2fa()` 重新要求 OTP 驗證；或將 `secret` 只存在短期伺服器記憶體/加密存放於 DB 並綁定 session
- 回傳 `qrCode` Data URL（含 `otpauth` secret）給前端，若前端記錄、分享、或被 XSS 讀取，即洩漏完整 TOTP secret
  影響：2FA 被複製
  建議：避免將 Data URL 長期保存；可改用短期圖檔 URL、且前端明確禁止保存與日誌紀錄

## Bugs / Logic issues（可能的 bug 或邏輯問題）
- `setup2fa()` 未檢查 `users.twofa_enabled`，已啟用 2FA 的使用者仍可發起 `setup2fa()`
  影響：產生多個 pending key 與 nonce，可能讓舊 nonce 被覆蓋或混淆
  建議：在 `setup2fa()` 先查 DB，若已啟用則回 409 或直接提示已開啟
- `setup2fa()` 對 Redis `set` 失敗僅回 503，但沒有清理已產生的 `secret`（僅在記憶體）
  影響：此處影響較小，但流程與錯誤訊息可能誤導
  建議：回應訊息包含重試建議或 trace id，方便追蹤
- `issuer` 固定為 "MyApp"，若同一使用者跨環境（dev/stage/prod）重複掃描，Authenticator 內帳號會撞名
  影響：使用者難以分辨帳號，容易誤刪
  建議：使用環境變數或品牌設定

## Design / Architecture（架構與模組切分建議）
- `setup2fa()` 與 `enable2fa()` 的 Redis key 以 `userId + nonce` 組合，但未與 session/refresh token 綁定
  建議：綁定 session identifier 或 user agent hash，降低 nonce 被重用或攔截後跨裝置啟用
- 缺少 `writeUserLogToDB()` 記錄 2FA 設定開始流程
  建議：新增 log 事件（如 `UserLogActionEnum.SETUP_2FA`）提升稽核能力

## Consistency / Style（命名、錯誤處理、logging、typing）
- `issuer`、`accountName` 直接硬編碼/直接使用 email，建議集中於 config 或 env，並與其他 auth 邏輯一致
- 錯誤訊息在 `setup2fa()` 與 `enable2fa()` 並未包含任何可追蹤資訊（例如 request id），與其他 API log 風格不一致
- `expiresInSec` 回傳固定 600，卻沒有依 `ttlSec` 變數，建議回傳 `ttlSec` 保持一致

## Actionable checklist（可直接執行的待辦事項，使用 `- [ ]`）
- [ ] 在 `src/controller/user.controllers.ts` 的 `setup2fa()` 增加檢查 `twofa_enabled`，已啟用時回 409
- [ ] 將 `issuer` 改為環境化設定（例如 `process.env.APP_NAME`），避免多環境撞名
- [ ] 回傳 `expiresInSec` 改用 `ttlSec`，避免硬編碼不一致
- [ ] 新增 `writeUserLogToDB()` 記錄 2FA setup 開始行為
